## 2. 判据与方法

- **max_z 成功率** = 物体举到参考峰 ±0.05 内的序列数 / 总数。
- **收敛** = 到达 90% 峰值 fair 的点。
- **env-steps** = iters × env × 32。
- **eval**：IG 用 100 env 取中位、mjlab 用 1 env（同一 max_z 判据）。
- **复现**：脚本 `dextrack_tools/repro_0703/`（IG/mjlab max_z eval + tb 指标读取 + README）；ckpt / tb / conda 环境在 HF（`migrate_install.sh` 拉齐）。

## 3. 结果

### 3.1 表1 — Isaac Gym (distance 门控) vs mjlab (contact 门控)

| 物体 | 模拟器 | 训练env | fair峰¹ | max_z成功率 | 收敛steps | 收敛时间 | 总steps |
|---|---|---|---|---|---|---|---|
| cube | Isaac Gym | 40000 | 112 | 4/6 | 3.0G | 32.2h | 4.2G |
| | **mjlab** | 24000 | 209 | **6/6** | **1.2G** | **12.7h** | 3.7G |
| cup | Isaac Gym | 40000 | 75 | 5/8 | 2.7G | 40.4h | 4.4G |
| | **mjlab** | 20000 | 161 | **6/8** | **1.3G** | **15.3h** | 3.4G |
| apple | Isaac Gym | 40000 | 58 | **1/8** | 3.9G | 39.0h | 6.0G |
| | **mjlab** | 22000 | 74 | 0/8 | **2.9G** | **36.4h** | 3.3G |
| 3obj | Isaac Gym | 40000 | 66 | 9/22 | 4.3G | 47.7h | 5.0G |
| | **mjlab** | 8000 | 132 | **16/22** | **1.9G** | **26.5h** | 2.6G |

¹ fair **不可跨模拟器比绝对值**（IG=`reward_fair` 距离门控、mjlab=`Episode/fair_reward` 接触门控，定义+归一化不同）。跨模拟器只看 max_z。

**结论**：mjlab(contact) max_z 全面 ≥ IG(distance)（cube 6/6>4/6、cup 6/8>5/8、3obj 16/22>9/22；apple 都差）；**收敛更快**（步数 / 时间普遍减半，cube 12.7h vs 32.2h）；用更少 env。

### 3.2 表2 — mjlab：单物体专项 vs 3obj 生成器（同物体序列）

| 物体 | run | fair² | max_z成功率 | 收敛steps | 收敛时间 |
|---|---|---|---|---|---|
| cube | 专项 | 209 | 6/6 | 1.2G | 12.7h |
| | **3obj 生成器** | 132 | **6/6** | 1.9G | 26.5h |
| cup | 专项 | 161 | 6/8 | 1.3G | 15.3h |
| | **3obj 生成器** | 132 | **7/8** | 1.9G | 26.5h |
| apple | 专项 | 74 | 0/8 | 2.9G | 36.4h |
| | **3obj 生成器** | 132 | **3/8** | 1.9G | 26.5h |

² 3obj fair=132 是三物体聚合（一个 run），非按物体拆；收敛 steps/时间也是该一个 run 共享。

**结论**：3obj 生成器每个物体上 ≥ 专项（cube 平、cup 7/8>6/8、apple 3/8>0/8）。且是**一个 run 全包**（1.9G 收敛 / 2.6G 总 / 26.5h）vs 三个专项合计（≈5.4G 收敛 / 10.4G 总 / ≈64h）——**~1/4 计算、结果更好**（apple 0/8→3/8，多物体迁移带起重物）。

## 4. apple 深挖 + 更大 env

- **apple 举不起 = 缺多物体迁移，不是 env 数、也不是抓力**：apple 单物体专项在 **8000 env 与 22000 env 都 0/8**（env 数无关）；加抓力 **kp×8 也只 1/8**（边际）；只有 3obj 生成器 **3/8**（表2）。机理 = 专项陷「趴地悬停」局部最优、不敢举升，3obj 从轻 cube/cup 迁移出「敢举升」。可视化：`wuji-mjlab/dextrack_tools/figs/`（3 图）+ `mjlab_apple_cmp_s2/s4.mp4`（左=专项趴地 / 右=3obj 举起）。
- **3obj 单卡能否上更大 env？不能**：park 方案撞显存墙（单卡上限 8000）；「每 env 只放 1 物体、reset 换 mesh」的 swap 方案能到 22000，但 **10× 慢**（129s/it）且训练在 apple 退化——要更大 env 只能多卡 DDP。

## 5. 进行中（2026-07-03）

**5.1 apple 从零消融**（找让 apple 专项能举的改动；全对照 exp1 = apple 8000env 0/8，改动全为默认关开关）

诊断：reward 让"趴地悬停"比举升更划算——① `object_pos_tracking` 接触门控 → 松手不碰=惩罚豁免（逃生门）② `inplace_bonus` 地板期就白给 ③ episode 跑满 300 帧、趴地也领满分。9 个变体：

| 变体 | 改动 | 针对 |
|---|---|---|
| R1 | object_pos 惩罚去门控（松手照罚） | 逃生门 |
| R2 | bonus 限举升期（ref_z 抬起才给） | 地板白给 |
| R3 | contact_guide 挂物体进度门控 | 悬停收入 |
| R123 | R1+R2+R3 | 组合 |
| MassCur | apple 质量 0.3→1.0× 退火 | 重 |
| RSI | 随机起始帧（半空持握态起步） | 探索死锁 |
| ET | 物体掉队即终止 episode | 趴地断粮 |
| Noise / Friction | init_std↑ / 摩擦↑ | 探索 / 打滑 |

> smoke 强信号：**R1 去门控在 smoke 里 8/8 vs 门控 0/8**，逃生门大概率是主因。

**状态**：首波 5 个已起训（GPU5=MassCur / 6=R123 / 0=R1 / 1=R2 / 7=R3，8000env/10000iter，~11.5s/it、ETA ~32h/个），队列脚本自动腾卡续 RSI→ET→Noise→Friction。评估：~5000iter 中途 max_z（`eval_apple_maxz.py`，对照 exp1 0/8）。

**5.2 specialist→generalist 蒸馏（可 scale 架构）**：不用 park/swap（塞多物体进一个仿真，撞显存/速度墙），改 **N 个单物体实例 + 共享 student**——每实例走 mujoco-warp 快路径、能上各自单卡上限，多物体性在网络里（256-d latent 区分），几百物体=抽 k 个轮转。DAgger 在线蒸馏（老师在 student 探索的 state 上标注 + BC 损失，`supervised_coef` 开关）。**副产品**：`coef=0` 即纯 PPO 多实例 generalist，是 park 3obj 的正统升级（更快/大 env/无污染），待跑通后对比 16/22。

**状态**：训练中（GPU3，3×8000=24000 env，34s/it≈park22000 正常速+小 BC 开销 vs swap 灾难性 129s）。MultiVecEnv + 老师标注 + BC（改 in-tree rsl_rl，coef=0 回归验证过不破坏普通训练）。老师=现有 cube/cup/apple 专项（都 ≤3obj，近期目标跑通基建、非超 16/22）。~3000iter 中途 eval。

**5.3 TopoRetarget 重定向（换更好的训练数据）**：现有 keypoint 重定向（FPOS）目标里没物体→接触漂移+穿透严重（apple 拇指戳穿 ~16mm）。改用 **TopoRetarget**（清华 CoRL2026，交互图+Laplacian 保接触结构、穿透作 SQP 约束）→ apple 穿透 **16mm→1.1mm（一个数量级）**。管线/门槛详见 [wuji_retargeting_and_visualization.md](wuji_retargeting_and_visualization.md) §一·补（逐序列 fit_crop + canonical ×1.25 尺度重定向 + Topo 完整 26-DOF 替代老步1+2+3 + wrist 朝向硬门槛防约定 bug）。对比视频 `mjlab_topo_vs_fpos_apple_s2_refstyle.mp4`（峰值帧 FPOS 16.7mm vs Topo 1.1mm，逐帧对齐）。

**状态**：全量重生成 cube+cup+apple → 新目录 `GRAB_Tracking_PK_WUJI_TOPO_v1`（62/84 过门槛，穿透 ~1.2mm vs FPOS 17.6mm=15×↓；no-offset + TOPO 自己 link_key 生成的 B2 接触，与 FPOS_v1 同结构，不覆盖）。待重训对比穿透改善是否转化成 tracking 成功率↑（paper 宣称 >40 点）。

## 6. 总结

1. **PhysX→MuJoCo + 接触门控**：成功率更高、收敛更快、更省 env（表1）。
2. **mjlab 内多物体生成器 > 单物体专项**，且省 ~4× 计算（表2）。
3. **apple 靠多物体迁移**才举得起，env 数 / 抓力 / 单卡更大 env 都不解决（§4）。
