## 2. 判据与方法

- **跟踪成功率**（通用，替代 max_z）= 满足下列的序列数 / 总数（**不看朝向**——球对称物体朝向无意义）：
  ① 活跃帧（参考位移 >2cm 或 旋转 >15°）中「位置误差 <5cm **且** 接触 ≥2 指」的占比 ≥ 阈值（0.50 宽 / 0.90 严）；
  ② 实际举高 ∈ [0.5×参考举高, 参考举高+0.3]（够到参考举升、且没飞走）。
  frac 单看位置会漏"贴地没举起"、单看接触会漏"握着但没跟上"，故两者与举高联合。
- **max_z 成功率**（旧）= 物体举到参考峰 ±0.05 内的序列数 / 总数。
- **收敛** = 到达 90% 峰值 fair 的点。
- **env-steps** = iters × env × 32。
- **eval**：IG 用 100 env 取中位、mjlab 用 1 env（同一 max_z 判据）。
- **复现**：脚本 `dextrack_tools/repro_0703/`（IG/mjlab max_z eval + tb 指标读取 + README）；ckpt / tb / conda 环境在 HF（`migrate_install.sh` 拉齐）。

|---|---|---|---|---|---|---|---|
| cube | Isaac Gym | 40000 | 112 | 4/6 | 3.0G | 32.2h | 4.2G |
| | **mjlab** | 24000 | 209 | **6/6** | **1.2G** | **12.7h** | 3.7G |
| cup | Isaac Gym | 40000 | 75 | 5/8 | 2.7G | 40.4h | 4.4G |
| | **mjlab** | 20000 | 161 | **6/8** | **1.3G** | **15.3h** | 3.4G |
| apple | Isaac Gym | 40000 | 58 | **1/8** | 3.9G | 39.0h | 6.0G |

## 4. apple 深挖 + 更大 env

- **apple 举不起 = 缺多物体迁移，不是 env 数、也不是抓力**：apple 单物体专项在 **8000 env 与 22000 env 都 0/8**（env 数无关）；加抓力 **kp×8 也只 1/8**（边际）；只有 3obj 生成器 **3/8**（表2）。机理 = 专项陷「趴地悬停」局部最优、不敢举升，3obj 从轻 cube/cup 迁移出「敢举升」。可视化：`wuji-mjlab/dextrack_tools/figs/`（3 图）+ `mjlab_apple_cmp_s2/s4.mp4`（左=专项趴地 / 右=3obj 举起）。
- **3obj 单卡能否上更大 env？不能**：park 方案撞显存墙（单卡上限 8000）；「每 env 只放 1 物体、reset 换 mesh」的 swap 方案能到 22000，但 **10× 慢**（129s/it）且训练在 apple 退化——要更大 env 只能多卡 DDP。

## 6. 总结

1. **PhysX→MuJoCo + 接触门控**：成功率更高、收敛更快、更省 env（表1）。
2. **mjlab 内多物体生成器 > 单物体专项**，且省 ~4× 计算（表2）。
3. **apple 靠多物体迁移**才举得起，env 数 / 抓力 / 单卡更大 env / **低穿透 TOPO 数据**都不单独解决（§4、§5.3 exp一 0/8）。
4. **fair 不预测举升**：fair 53/71 仍 0/8，消融只能靠 max_z eval 定优劣（§5.1）。
5. **验证 TOPO 要选有余量的 setup**：apple 专项是 0/8 地板显不出数据差异，改用 3obj 生成器 A/B（§5.3 exp二，进行中）。

## 9. 补训 TOPO+MassCur apple 专项（进行中）

**要验证**：「混合训练 vs 专项」此前拿 **FPOS 专项** 比 **TOPO 生成器**，是**跨数据、不公平**。需同数据同配置的 apple 专项做基线，才能判断"混合是否掉点"。

| apple | 无 MassCur | 带 MassCur |
|---|---|---|
| FPOS 专项 | 2 | 16 |
| TOPO 专项 | 6 | **17**（@5000 ×3 全 17）|
| FPOS 生成器 | 5 | 3（异常，见下） |
| TOPO 生成器 | 8 | 14 |

- **结论（已补训验证）**：同数据同配置 TOPO+MassCur，**专项 apple 17 vs 生成器 14——只差 3**。「混合≈专项」成立：生成器仅在最难的 apple 掉 3 分，cube/cup 持平/反超。
- 完整公平对比（cube/cup 用 FPOS 专项代理，低穿透物体 TOPO≈FPOS）：**TOPO 专项 ~62 vs TOPO 生成器 59**。一个 run 全包 + 算力 1/3，几乎不掉点。

**附：一起-FPOS apple=3 的异常**（排查结论）：非训练进度/数据/多物体本身，也**非 MassCur 代码 bug**（已逐项验证：事件挂 apple、MultiVecEnv 内 counter 正常、质量退火 0.3→1.0× 精确、mass-scale 无关）。表现为 **MassCur × FPOS-生成器** 的训练动力学问题（同数据专项能 16、同配置 TOPO 生成器能 14）。暂不进 presentation，留排查。
